# Архитектура лабораторных №5–6

## Дополнение ЛР6: Repository

Модели и ошибки находятся в internal/domain. Интерфейсы Protocol — в
internal/repository/interfaces.py; они не импортируют драйвер. Реализации четырёх
репозиториев используют psycopg в internal/repository/postgres. Общая механика
CRUD вынесена в base.py, фиксированные SQL-запросы — в user.py, hotel.py, room.py,
booking.py. Сервис каталога получает репозитории через конструктор.

BookingService зависит от интерфейса UnitOfWork. PostgresUnitOfWork открывает
транзакцию и передаёт всем репозиториям один TransactionConnection. Сервис задаёт
порядок: блокировка номера -> проверка гостя и статуса -> проверка пересечения ->
создание брони. SQL остаётся в репозиториях. Изоляция PostgreSQL — READ COMMITTED;
повторная проверка пересечения после ожидания блокировки видит последнюю фиксацию.

Четыре репозитория проверены 19 интеграционными тестами на отдельной базе.
Основная БД не очищается тестами. Маршруты /lab6/hotels и /lab6/rooms/{id}
демонстрируют чтение через все слои. Полный API из ЛР2 — отдельный будущий этап.

Порты Lab_6 — 8086/5436, Lab_5 — 8085/5435; у каждого Compose-проекта свой pgdata.
Ниже сохранено описание инфраструктуры ЛР5, на которой построена ЛР6.

```text
HTTP /health -> HealthHandler -> HealthService -> HealthRepository (Protocol)
                                                     ^
                                                     |
                                         PostgresHealthRepository
                                                     |
                                            psycopg ConnectionPool -> PostgreSQL
```

main создаёт конфигурацию, пул и зависимости. Пул живёт до завершения приложения;
его верхняя граница — DB_MAX_CONNS (10), минимум — 1, срок жизни соединения —
30 минут, допустимый простой — 5 минут. Получение соединения и SQL имеют таймауты.
При старте: до 10 попыток с ограниченной растущей паузой. После сбоя PostgreSQL
пул заменяет сломанные соединения. SIGINT/SIGTERM завершает HTTP и закрывает пул.

## Схема и нормализация

Сохранены пять сущностей ERD из ЛР1: users, hotels, rooms, bookings, reviews.
Добавлены password_hash для будущей авторизации и created_at для стабильной
сортировки. Роли, категории и статусы совпадают с OpenAPI из ЛР2.

Схема соответствует 3НФ: атомарные поля; каждый неключевой атрибут зависит от ключа
своей таблицы; имя пользователя и адрес отеля не повторяются в bookings.
total_cost — историческая сумма конкретного бронирования, а не вычисление по
текущему тарифу номера. hotels.rating — отдельная опубликованная оценка отеля
из исходной ERD; это не автоматически пересчитываемый AVG(reviews.rating).
Если потребуется именно среднее отзывов, его следует вычислять запросом/представлением.

| Связь | ON DELETE | Обоснование |
|---|---|---|
| rooms -> hotels | RESTRICT | Нельзя удалить отель с номерами |
| bookings -> users | RESTRICT | Не теряем историю бронирований при удалении гостя |
| bookings -> rooms | RESTRICT | Не теряем историю при удалении номера |
| reviews -> users/hotels | CASCADE | Отзыв не имеет смысла без автора/отеля |

Индексы FK: bookings.user_id, составной bookings(room_id, check_in_date,
check_out_date), reviews.hotel_id созданы явно. rooms.hotel_id и reviews.user_id
уже покрыты первыми столбцами UNIQUE-индексов — дублировать их не нужно.
UNIQUE действует также на email и номер комнаты внутри отеля.
CHECK защищает цену, вместимость, рейтинг, даты, роли и статусы.
Деньги — NUMERIC(12,2); даты проживания — DATE; техническое время — TIMESTAMPTZ.
Начальная миграция и её откат атомарны (BEGIN/COMMIT). Порядок DROP обратный зависимостям.

## Контейнеры

PostgreSQL 16 хранит данные в pgdata. migrate/migrate:v4.18.1 ждёт healthy базы
и завершается после применения миграции; приложение ждёт его успешного завершения.
Миграции монтируются read-only. Dockerfile устанавливает закреплённые psycopg 3
и psycopg_pool. .env не входит в Git или образ. Порты опубликованы на loopback.

Учебное ограничение: POSTGRES_USER одновременно владелец БД и пользователь приложения;
в production мигратору и приложению выделяют разные роли с минимальными правами.
SSL отключён только для локальной Compose-сети.
