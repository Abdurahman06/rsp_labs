# Лабораторная работа №6 — Repository / Data Access Layer

Тема: бронирование номеров в городских отелях. Работа продолжает ветку lab_5.
Схема миграции из ЛР5 сохранена без изменения.

## Запуск и проверка (PowerShell)

```powershell
Copy-Item .env.example .env
# Замените DB_PASSWORD на локальный пароль из латинских букв и цифр.
docker compose up --build -d
curl.exe -i http://127.0.0.1:8086/health
python scripts/verify_lab6.py
```

На компьютере, где работа выполнена, .env уже подготовлен.
В Git он не хранится. Порты: HTTP 8086, PostgreSQL 5436.
Скрипт создаёт отдельную lab6_test_* БД, применяет миграцию,
запускает **19 интеграционных тестов** и пример бронирования, затем удаляет только
созданную им БД. Основная hotels не очищается.
Python на хосте нужен только для запуска скрипта, зависимости приложения выполняются в Docker.

## Реализовано

- Доменные модели User, Hotel, Room, Booking, Review. Денежные поля — Decimal.
- Отдельные Protocol-интерфейсы и PostgreSQL-реализации четырёх репозиториев:
  users, hotels, rooms, bookings.
- create / get_by_id / list / delete у всех четырёх;
  update у rooms; get_by_email у users.
- INSERT RETURNING, явные столбцы, параметры %s, стабильная пагинация (максимум 100).
- ErrNotFound, ErrAlreadyExists, ErrConflict, ErrInvalidInput; исходная ошибка
  драйвера сохранена в __cause__.
- BookingService + Unit of Work: блокировка номера, проверка пересечения и создание
  брони в одной транзакции. Есть тест с двумя одновременными запросами.
- Преобразование модели в JSON через to_public скрывает password_hash.

## Наглядная демонстрация

`python scripts/verify_lab6.py` сохраняет результат в docs/evidence/lab6.json.
Он показывает создание брони на две ночи по 3000.50, сумму 6001.00 и отказ второй
броне с пересекающимися датами. Демонстрационные записи удаляются вместе с тестовой БД.

Дополнительные маршруты только для чтения позволяют увидеть цепочку
HTTP -> service -> repository -> PostgreSQL:

```powershell
curl.exe -i "http://127.0.0.1:8086/lab6/hotels?limit=2&offset=0"
curl.exe -i http://127.0.0.1:8086/lab6/rooms/not-a-uuid
curl.exe -i http://127.0.0.1:8086/lab6/hotels/00000000-0000-0000-0000-000000000001
```

Ожидаются 200 (пустой список в новой основной базе), 400 и 404.
Также есть GET /lab6/hotels/{id} и GET /lab6/rooms/{id}.
Это демонстрационные маршруты ЛР6. OpenAPI из ЛР2 остаётся проектом полного API:
авторизация, публичное создание брони и другие бизнес-маршруты ещё не реализованы.
